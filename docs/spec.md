## 0. Мета
- **Команда:** Mood Diary
- **Гипотеза:** см. `hypothesis.md`
- **Версия спеки / дата:** v0.2 / 2026-07-09
- **Основание для v0.2:** уточнения по итогам `docs/review_spec.md`.

## 1. Обзор и цель
Mood Diary — privacy-first дневник настроения для работающих людей, которым сложно регулярно вести длинные записи, но важно раньше замечать ухудшение состояния. Продукт помогает за 15–20 секунд в день зафиксировать состояние, увидеть первые паттерны уже после 3–5 записей и получить одну мягкую рекомендацию без диагностики и давления.

Главная ценность прототипа: пользователь быстро понимает, просматривается ли в его данных связь между сном и настроением, и видит маленькое действие, которое можно попробовать завтра.

## 2. Целевые пользователи
- **Основной пользователь:** работающий человек 22–40 лет с плотным графиком, который периодически замечает спады настроения, энергии или рост тревожности, но не ведёт системного трекинга.
- **Early adopter:** молодой специалист 25–35 лет, которому важно следить за ментальным состоянием, но нет времени и дисциплины на длинные дневниковые записи.
- **Вторичный сценарий:** человек, который уже работает со специалистом и хочет приносить на сессии краткую историю состояний и триггеров.

## 3. Границы (scope)
**В скоупе P0:**
- Быстрый daily check-in за 15–20 секунд.
- 5 базовых шкал: настроение, энергия, тревожность, стресс, сон.
- Фиксированный словарь предустановленных тегов контекста дня.
- Первый инсайт по правилу «сон ↔ настроение» после 3–5 записей.
- Одна мягкая рекомендация, если найден паттерн сна и настроения.
- Прогресс до первого инсайта в формате количества записей.
- История последних 14 записей.
- Компактный график сна и настроения за последние 7 календарных дней.
- Оценка полезности инсайта в формате «полезно / не полезно / пропустить».
- Дисклеймер «не диагноз и не замена специалиста».
- Безопасная палитра без красного как маркера «плохо».
- Удаление отдельной записи и всех данных приложения.
- Полная работа P0 без интернета, аккаунта, облачной синхронизации и внешних аналитических SDK.
- Экспорт анонимной статистики использования (только счётчики, без mood-данных) для оценки критерия успеха командой.

**В скоупе после P0, если остаётся время (P1):**
- Короткий комментарий по желанию.
- Недельный обзор.
- Авто-теги из комментария по локальному словарю ключевых слов.

**Вне скоупа MVP:**
- Интеграции с wearable, Health Connect, Apple Health, трекерами сна, календарём и экранным временем.
- Push-уведомления.
- Полноценный ML-анализ, LLM-анализ личных записей и медицинская диагностика.
- Консультации специалистов внутри продукта.
- Социальные функции.
- Веб-версия.
- Платные внешние API.
- Обязательная авторизация.
- Голосовой ввод, пользовательские теги, месячный календарь, PIN/Face ID, ИИ-сводка недели.
- Сторонняя аналитика поведения пользователя.
- Стрики, бейджи, соревновательная геймификация и отдельная функция отключения геймификации.

## 4. Доменная модель

### 4.1 Entry
Одна дневниковая запись за один локальный календарный день.

Поля:
- `id` — уникальный идентификатор записи.
- `date` — локальная календарная дата записи в часовом поясе устройства на момент создания или редактирования.
- `mood` — настроение, целое число 1–5.
- `energy` — энергия, целое число 1–5.
- `anxiety` — тревожность, целое число 1–5.
- `stress` — стресс, целое число 1–5.
- `sleep` — субъективная оценка сна, целое число 1–5.
- `tags` — список выбранных `Tag.id`, может быть пустым.
- `comment` — короткий комментарий, только для P1, может быть пустым.
- `createdAt` — дата и время создания.
- `updatedAt` — дата и время последнего изменения.

Правила:
- В P0 допускается только одна запись на один локальный календарный день.
- Повторный check-in за тот же день открывает редактирование существующей записи, а не создаёт вторую запись.
- Запись можно редактировать в день создания и позже через историю.
- При смене часового пояса уже сохранённая `date` не пересчитывается задним числом.
- Две записи в 23:58 и 00:03 относятся к разным локальным календарным датам.

### 4.2 Tag
Фиксированный тег контекста дня.

Словарь P0:

| id | Название в UI | Категория |
|---|---|---|
| `work` | Работа | Нагрузка |
| `deadline` | Дедлайн | Нагрузка |
| `conflict` | Конфликт | Социальное |
| `meeting` | Много встреч | Нагрузка |
| `rest` | Отдых | Восстановление |
| `walk` | Прогулка | Восстановление |
| `sport` | Спорт | Активность |
| `social` | Общение | Социальное |
| `family` | Семья | Социальное |
| `health` | Самочувствие | Тело |
| `screen_time` | Много экрана | Контекст |
| `chores` | Бытовые дела | Контекст |

Правила:
- В P0 пользователь не создаёт собственные теги.
- Выбор тегов необязателен для сохранения записи.
- В аналитике P0 теги отображаются в истории, но первый инсайт строится только по `sleep` и `mood`.

### 4.3 Insight
Инсайт — результат проверки правила «сон ↔ настроение».

Поля:
- `type` — для P0 всегда `sleep_mood`.
- `status` — `waiting`, `found`, `no_clear_pattern` или `not_enough_data`.
- `subtype` — уточняет ветку:
  - Для `status = found`: `contrast` (стандартная, есть обе группы), `stable_low` (стабильно низкий сон), `stable_high` (стабильно высокий сон и хорошее настроение).
  - Для `status = no_clear_pattern`: `no_polarity` (нет ни одного полюса low_sleep или high_sleep, либо один полюс есть, но стабильное состояние не подтверждено), `no_correlation` (обе группы есть, но разница настроения < 1.0), `intermediate` (всё остальное — fallback).
  - Для `waiting` и `not_enough_data` — `null`.
- `entriesUsed` — список дат записей, учтённых в расчёте; хранится внутренне. В UI отображается как количество (например, «использовано 5 записей»), а не список дат.
- `secondaryObservations` — список вторичных паттернов по шкалам energy, anxiety, stress. Каждый элемент: `{ scale: "energy"|"anxiety"|"stress", direction: "better_sleep_higher"|"better_sleep_lower"|"stable" }`. Пустой список, если паттернов нет или данных недостаточно. В P0 показывается не более одного элемента.
- `message` — текст для пользователя.
- `confidenceLabel` — `низкая` или `средняя`; высокая уверенность в MVP не используется. Правила присвоения: `found / contrast` при 3–4 записях → `низкая`; `found / contrast` при 5+ записях → `средняя`; `found / stable_low` и `found / stable_high` (независимо от количества записей) → `низкая`, так как сравнение групп невозможно.
- `generatedAt` — дата и время расчёта.

Правила:
- Инсайт пересчитывается после создания, редактирования или удаления записи.
- Удалённые записи не участвуют в инсайтах.
- Инсайт не использует комментарии и не делает выводов о причинах, личности или диагнозах.

### 4.4 Recommendation
Рекомендация — одно маленькое действие, привязанное к найденному паттерну.

Поля:
- `insightType` — тип инсайта, для P0 `sleep_mood`.
- `message` — бережная формулировка действия.
- `shownForDate` — дата показа.

Правила:
- Основная рекомендация показывается только для `Insight.status = found`.
- Если связь не найдена или данных мало, вместо рекомендации показывается нейтральное сообщение о продолжении наблюдения.
- За один показ пользователь видит не больше одной основной рекомендации.

### 4.5 InsightFeedback
Оценка полезности инсайта.

Поля:
- `insightType` — тип инсайта.
- `shownAt` — дата и время показа.
- `value` — `useful`, `not_useful` или `skipped`.

### 4.6 AppEvent
Анонимное событие для измерения критерия успеха (hypothesis.md §5). Не содержит mood-данных, личных записей или идентификаторов пользователя.

Поля:
- `id` — уникальный идентификатор события.
- `eventType` — тип события; в P0 единственный тип: `insight_screen_opened`.
- `occurredAt` — дата и время события.

Правила:
- Запись создаётся при каждом открытии экрана инсайтов; дедупликация не применяется (нужна частота, а не уникальность).
- Удаляется при удалении всех данных приложения наравне с записями и оценками.

## 5. Формальная логика первого инсайта

### 5.1 Какие записи участвуют
- Используются последние 7 записей по `date`, но не больше фактически существующего количества записей.
- Минимум для расчёта — 3 записи.
- Удалённые записи не учитываются.
- Комментарии и теги не участвуют в расчёте инсайта. Энергия, тревожность и стресс не участвуют в основном расчёте, но проверяются как вторичные наблюдения по тем же записям (см. 5.3.1).

### 5.2 Правило 3–5 записей
- **0–2 записи:** показывается прогресс, инсайт не рассчитывается, статус `not_enough_data`.
- **3–4 записи:** система пытается показать мини-инсайт только при явной связи. Если явной связи нет, показывается прогресс до 5 записей, статус `waiting`.
- **5+ записей:** система обязательно показывает либо найденный инсайт (`found`), либо бережное сообщение «связь пока не просматривается» (`no_clear_pattern`).

### 5.3 Как определяется связь
Для каждой записи:
- `low_sleep` — `sleep <= 2`.
- `high_sleep` — `sleep >= 4`.

Связь считается найденной при выполнении всех условий:
- В учтённых записях есть минимум одна запись `low_sleep` и минимум одна запись `high_sleep`.
- Среднее настроение в `high_sleep` записях выше среднего настроения в `low_sleep` записях минимум на 1.0 балл.
- Для 3–4 записей дополнительно требуется явный контраст: все `low_sleep` записи имеют `mood <= 3`, а все `high_sleep` записи имеют `mood >= 3`.

Связь считается не найденной, если выполняется любое условие:
- Все оценки сна одинаковые или отличаются только в пределах одной соседней оценки без групп `low_sleep`/`high_sleep`.
- Нет одновременно группы `low_sleep` и группы `high_sleep`.
- Разница средних настроений между `high_sleep` и `low_sleep` меньше 1.0 балла.
- Настроение меняется противоречиво: часть дней с низким сном имеет более высокое настроение, чем дни с высоким сном, и средняя разница меньше порога.

Примеры:
- Сон `5 4 5 4 5`, настроение `3 4 3 4 3`: нет группы `low_sleep`; `stable_high` не выполнено (avg(mood) = 3.4 < 3.5) → `status = no_clear_pattern`, `subtype = no_polarity`; показывается шаблон `no_clear_pattern / no_polarity` из §5.4.
- Сон `5 5 5`, настроение `1 5 3`: только 3 записи, нет группы `low_sleep` → явной связи нет → `status = waiting`; показывается шаблон `waiting` из §5.4.
- Сон `2 5 2 4 5`, настроение `2 4 3 4 5`: связь найдена; пользователь видит осторожный инсайт о том, что в днях с более высоким сном настроение в среднем было выше.

### Ветки стабильного состояния внутри `found`

Если условия стандартного `found` не выполнены (нет одновременно групп `low_sleep` и `high_sleep`), проверяются ветки стабильного состояния:

**found + stable_low** (стабильно низкий сон):
- Нет ни одной записи `high_sleep` (sleep ≥ 4).
- Более половины учтённых записей — `low_sleep` (sleep ≤ 2).
- `status = found`, `subtype = stable_low`; рекомендация показывается.

**found + stable_high** (стабильно высокий сон с хорошим настроением):
- Нет ни одной записи `low_sleep` (sleep ≤ 2).
- Более половины учтённых записей — `high_sleep` (sleep ≥ 4).
- Среднее `mood` по учтённым записям ≥ 3.5.
- `status = found`, `subtype = stable_high`; рекомендация показывается (Пул C).

**Промежуточные состояния** (сон без выраженных полюсов; или `stable_high` без хорошего настроения):
- Нет условий ни для одной ветки `found`.
- `status = no_clear_pattern`.

**Подтипы `no_clear_pattern`** (определяют, какой шаблон сообщения показывается):
- `no_polarity` — нет ни одной записи `low_sleep` И нет ни одной записи `high_sleep`; или один полюс присутствует, но стабильное состояние (`stable_low` / `stable_high`) не выполнено (нет нужного большинства или не достигнут порог среднего настроения для `stable_high`).
- `no_correlation` — присутствуют и `low_sleep`, и `high_sleep` записи, но `avg(mood | high_sleep) − avg(mood | low_sleep) < 1.0`.
- `intermediate` — всё остальное (fallback).

Примеры стабильных веток:
- Сон `2 1 2 1 2`, настроение `2 1 3 2 1`: нет `high_sleep`, более половины `low_sleep` → `found / stable_low`.
- Сон `5 4 5 4 5`, настроение `4 5 4 4 5`: нет `low_sleep`, более половины `high_sleep`, среднее mood = 4.4 → `found / stable_high`.
- Сон `3 3 3 3 3`, настроение `3 2 4 3 3`: нет ни одной группы → `no_clear_pattern`.
- Сон `5 4 5 4 5`, настроение `2 3 2 3 2`: нет `low_sleep`, `high_sleep` есть, но среднее mood = 2.4 < 3.5 → `no_clear_pattern`.

### 5.3.1 Вторичные наблюдения по энергии, тревожности и стрессу

Вторичные наблюдения рассчитываются по тем же записям, что и основной инсайт (минимум 3). Не рассчитываются при статусе `not_enough_data`.

Для каждой шкалы проверяется связь с качеством сна:

**Энергия (energy)** — ожидаемое направление: лучший сон → выше энергия:
- Паттерн найден, если `avg(energy | high_sleep) − avg(energy | low_sleep) ≥ 1.0`.
- Стабильно низкая: нет `high_sleep`-записей, более половины `low_sleep`, `avg(energy) ≤ 2.5`.

**Тревожность (anxiety)** — ожидаемое направление: лучший сон → ниже тревожность:
- Паттерн найден, если `avg(anxiety | low_sleep) − avg(anxiety | high_sleep) ≥ 1.0`.
- Стабильно высокая: нет `high_sleep`-записей, более половины `low_sleep`, `avg(anxiety) ≥ 3.5`.

**Стресс (stress)** — ожидаемое направление: лучший сон → ниже стресс:
- Паттерн найден, если `avg(stress | low_sleep) − avg(stress | high_sleep) ≥ 1.0`.
- Стабильно высокий: нет `high_sleep`-записей, более половины `low_sleep`, `avg(stress) ≥ 3.5`.

Правила отбора:
- Из всех найденных вторичных паттернов выбирается один с наибольшей абсолютной разницей средних.
- При равной разнице приоритет: `energy` > `anxiety` > `stress`.
- В P0 показывается максимум одно вторичное наблюдение.
- Если `low_sleep`/`high_sleep`-групп нет (стабильный сон), вторичный паттерн проверяется только по стабильным условиям выше.
- При `found / stable_high` вторичные наблюдения не рассчитываются: группа `low_sleep` отсутствует, сравнение невозможно. Показывается только основное сообщение `found / stable_high`.

### 5.4 Шаблоны сообщений инсайта
`found / contrast` (стандартная, есть обе группы):
> «В твоих последних записях прослеживается паттерн: в дни с лучшим сном настроение было заметно выше. Это не доказывает причинно-следственную связь — но достаточно устойчиво, чтобы понаблюдать за ним осознанно. Не диагноз — просто интересная закономерность».

`found / stable_low` (стабильно низкий сон):
> «Сон в последних записях стабильно низкий. Сравнить его с чем-то другим пока сложно — но стабильно низкий сон сам по себе фактор, который часто влияет на самочувствие в течение дня. Это не диагноз — просто наблюдение, которое стоит держать в голове».

`found / stable_high` (стабильно высокий сон и хорошее настроение):
> «Сон в последних записях стабильно хороший, и настроение держится уверенно. Значит, что-то в твоём нынешнем ритме работает. Стоит это замечать — и стараться сохранить, когда ритм будет под давлением».

`waiting`:
> n=1: «Уже есть первые записи. Чтобы не делать поспешный вывод, нужно ещё немного данных — осталась 1 запись до 5».
> n=2: «Уже есть первые записи. Чтобы не делать поспешный вывод, нужно ещё немного данных — осталось 2 записи до 5».

`not_enough_data`:
> n=1: «Пока данных мало. Ещё 1 запись — и можно будет проверить связь сна и настроения».
> n=2: «Пока данных мало. Ещё 2 записи — и можно будет проверить связь сна и настроения».
> n=3: «Пока данных мало. Ещё 3 записи — и можно будет проверить связь сна и настроения».

`no_clear_pattern / no_polarity` (нет выраженных полюсов: нет ни `low_sleep`, ни `high_sleep` — или один полюс есть, но стабильное состояние не подтверждено):
> «Сон в последних записях держался без выраженных контрастов — дней с заметно низким или заметно высоким сном пока недостаточно для сравнения. Продолжай отмечать — картина прояснится».

`no_clear_pattern / no_correlation` (сон менялся, но настроение не реагировало):
> «Сон менялся, но настроение в эти периоды двигалось независимо. Явной связи пока не видно — возможно, в этот промежуток больше влияли другие факторы. Это нормально».

`no_clear_pattern / intermediate` (промежуточные состояния — общий fallback):
> «В последних записях устойчивого паттерна между сном и настроением не нашлось. Паттерны часто проявляются позже или при большем разбросе данных — продолжай наблюдения».

**Вторичные наблюдения** — добавляются одной строкой после основного текста инсайта:

`energy / better_sleep_higher`:
> «Ещё одно наблюдение: в дни с лучшим сном энергия тоже была заметно выше».

`anxiety / better_sleep_lower`:
> «Ещё одно наблюдение: в дни с лучшим сном тревожность была заметно ниже».

`stress / better_sleep_lower`:
> «Ещё одно наблюдение: в дни с лучшим сном уровень стресса тоже был ниже».

`energy / stable`:
> «Ещё одно наблюдение: энергия в последних записях оставалась на низком уровне — это стоит иметь в виду при продолжении наблюдения».

`anxiety / stable`:
> «Ещё одно наблюдение: тревожность в последних записях была на повышенном уровне — это важный контекст для продолжения дневника».

`stress / stable`:
> «Ещё одно наблюдение: уровень стресса в последних записях оставался высоким — это важный контекст для продолжения дневника».

Правила вторичных наблюдений:
- Не показываются при статусе `not_enough_data`.
- Не генерируют отдельную рекомендацию — рекомендация остаётся одна, от основного инсайта.
- Показывается максимум одно вторичное наблюдение за раз.

**Подтверждение оценки инсайта** (InsightFeedback, US-6):

`useful`:
> «Хорошо — наблюдения становятся точнее с каждой записью».

`not_useful`:
> «Понятно. Продолжай отмечать — картина будет меняться».

`skipped`: подтверждение не показывается.

Тексты можно адаптировать под UI, но нельзя менять смысл: без диагнозов, обвинения, обещания лечения и категоричных причинно-следственных выводов.

### 5.5 Шаблоны рекомендаций

**Пул A — для `found / contrast`** (пользователь видит контраст: лучший сон = лучшее настроение):
- «Попробуй сегодня один небольшой шаг: лечь на 20 минут раньше — и завтра отметь, заметна ли разница в настроении».
- «Обрати внимание на то, что отличало твои дни с хорошим сном. Иногда это один привычный вечерний ритуал — его стоит сохранить».
- «Если подходит, продолжи наблюдать ещё несколько дней: паттерн станет виднее, и можно будет сделать более осознанный вывод».

**Пул B — для `found / stable_low`** (сон стабильно низкий — нет контраста для сравнения):
- «Можно начать с одного маленького шага этим вечером: попробуй лечь на 15 минут раньше обычного — без давления на результат».
- «Попробуй убрать экран за 30 минут до сна — и отметь завтра, изменилось ли что-то. Маленький эксперимент, один шаг».
- «Обрати внимание на свой вечерний ритм: что происходит за час до сна? Иногда небольшое изменение именно в этом промежутке заметнее всего».

**Пул C — для `found / stable_high`** (сон и настроение стабильно хорошие — акцент на сохранение ритма):
- «Отметь для себя, что сейчас работает хорошо — это поможет вернуться к этому ритму, если что-то изменится».
- «Попробуй понаблюдать, что именно в твоём вечернем ритме помогает хорошо спать — это стоит сохранить осознанно».
- «Обрати внимание на то, что помогает тебе сохранять этот ритм — осознанно замеченная привычка проще держится».

Правило выбора:
- `found / contrast` → Пул A; в P0 первый шаблон как основной.
- `found / stable_low` → Пул B; в P0 первый шаблон как основной.
- `found / stable_high` → Пул C; в P0 первый шаблон как основной.
- При `waiting`, `not_enough_data` или `no_clear_pattern` основная рекомендация не показывается.
- Если реализована ротация — детерминированная, не больше одной рекомендации за раз.

## 6. Карта экранов и состояния

### 6.1 Экраны P0
- **Home:** текущий статус дня, быстрый вход в check-in, прогресс до инсайта или последний инсайт.
- **Check-in / Edit Entry:** ввод или редактирование 5 шкал и тегов.
- **Insight:** первый инсайт, рекомендация при найденном паттерне, оценка полезности.
- **History:** последние 14 записей, просмотр деталей, редактирование и удаление записи.
- **Settings:** дисклеймер, privacy-first объяснение, удаление всех данных, экспорт анонимной статистики для команды.
- **Delete Data Confirmation:** подтверждение удаления всех данных приложения.

### 6.2 Экраны P1
- **Weekly Summary:** недельный обзор.

### 6.3 Состояния приложения
- **Первый запуск:** нет записей; пользователь видит короткий дисклеймер и вход в check-in.
- **0–2 записи:** показывается прогресс до 3 записей, инсайт не строится.
- **3–4 записи без явной связи:** показывается прогресс до 5 записей.
- **3–4 записи с явной связью:** показывается мини-инсайт со средней уверенностью.
- **5+ записей:** показывается найденный инсайт или сообщение, что связь пока не просматривается.
- **История пустая:** показывается пустое состояние и действие «создать запись».
- **Данные удалены:** приложение возвращается в состояние первого запуска.
- **Ошибка сохранения:** пользователь видит понятное сообщение, введённые значения остаются на экране до повторной попытки.

## 7. Пользовательские истории

### US-0 · [P0] Первый запуск
**Как** новый пользователь, **я хочу** сразу понять, что делает приложение и как защищены мои данные, **чтобы** начать вести дневник без лишних барьеров.

**Критерии приёмки:**
- [ ] При первом открытии без записей пользователь видит короткий дисклеймер (не более одного экрана).
- [ ] Дисклеймер содержит: краткое описание продукта, фразу «не диагноз и не замена специалиста», упоминание локального хранения данных на устройстве.
- [ ] После дисклеймера пользователь попадает прямо в check-in без дополнительных шагов настройки или регистрации.
- [ ] Приложение не запрашивает никаких разрешений операционной системы до первого check-in.
- [ ] Дисклеймер доступен повторно из раздела Settings.

### US-1 · [P0] Быстрый daily check-in
**Как** работающий пользователь, **я хочу** быстро отметить состояние дня, **чтобы** вести дневник без ощущения длинной обязанности.

**Критерии приёмки:**
- [ ] Пользователь может создать или обновить запись за текущий локальный календарный день.
- [ ] В записи есть 5 шкал с оценками 1–5: настроение, энергия, тревожность, стресс, сон.
- [ ] Пользователь может выбрать 0 или больше тегов из фиксированного словаря P0.
- [ ] Основной путь создания записи не требует свободного текста.
- [ ] Основной путь укладывается в один экран check-in и не больше одного экрана подтверждения.
- [ ] Для сохранения требуется не больше 7 обязательных пользовательских действий: выбрать 5 оценок, при необходимости открыть check-in, нажать «сохранить».
- [ ] Теги и комментарий не блокируют сохранение записи.
- [ ] Проверка времени: в демонстрационном happy path повторный пользователь сохраняет запись за ≤20 секунд в 2 из 3 попыток.

### US-2 · [P0] Первый инсайт: сон ↔ настроение
**Как** пользователь, который сделал несколько записей, **я хочу** увидеть первый понятный инсайт, **чтобы** понять, какие факторы могут быть связаны с моим состоянием.

**Критерии приёмки:**
- [ ] При 0–2 записях инсайт не показывается; показывается прогресс до 3 записей.
- [ ] При 3–4 записях инсайт показывается только при выполнении правила явной связи из раздела 5.3.
- [ ] При 3–4 записях без явной связи показывается ожидание до 5 записей.
- [ ] При 5+ записях пользователь видит либо инсайт `found`, либо сообщение `no_clear_pattern`.
- [ ] Инсайт объясняет, сколько записей учитывалось в расчёте (например, «использовано 5 записей»).
- [ ] Инсайт не содержит диагнозов, медицинских выводов или категоричных утверждений о личности пользователя.

### US-3 · [P0] Одна мягкая рекомендация
**Как** пользователь, который увидел найденный инсайт, **я хочу** получить одно маленькое действие, **чтобы** попробовать улучшить состояние без давления и банальных советов.

**Критерии приёмки:**
- [ ] Рекомендация показывается рядом с найденным инсайтом `sleep_mood`.
- [ ] Рекомендация выбирается из шаблонов раздела 5.5.
- [ ] При `waiting`, `not_enough_data` и `no_clear_pattern` основная рекомендация не показывается.
- [ ] За один раз показывается не больше одной основной рекомендации.
- [ ] Формулировка рекомендации бережная: «можно попробовать», «обрати внимание», «если подходит», а не приказ или диагноз.
- [ ] Рекомендация не обещает лечения и не заменяет консультацию специалиста.

### US-4 · [P0] Прогресс до первого инсайта
**Как** новый пользователь, **я хочу** понимать, сколько записей осталось до первого инсайта, **чтобы** видеть раннюю ценность и не бросить дневник в первые дни.

**Критерии приёмки:**
- [ ] До 3 записей пользователь видит прогресс в формате «{x}/3 записей до первой проверки сна и настроения».
- [ ] При 3–4 записях без явной связи пользователь видит прогресс в формате «{x}/5 записей для более осторожного вывода».
- [ ] После 5 записей прогресс до первого инсайта больше не показывается как основное состояние.
- [ ] Сообщение сформулировано нейтрально и без давления.
- [ ] Пропуск дня не сопровождается формулировками «провал», «стрик потерян» или похожими наказующими сообщениями.
- [ ] Формат «{x}/5» описывает визуальный счётчик или прогресс-бар. Текстовое сообщение из шаблона §5.4 (`waiting`) отображается рядом как подзаголовок инсайт-блока. Оба элемента присутствуют одновременно.

### US-5 · [P0] История последних записей
**Как** пользователь, **я хочу** видеть последние записи, **чтобы** понимать динамику своего состояния и проверять, что дневник сохраняется.

**Критерии приёмки:**
- [ ] Пользователь видит последние 14 записей, отсортированные от новых к старым.
- [ ] Для каждой записи видны дата, настроение, сон и выбранные теги.
- [ ] Пользователь может открыть запись для просмотра деталей.
- [ ] Пользователь может отредактировать запись.
- [ ] Пользователь может удалить отдельную запись после подтверждения.
- [ ] Удалённая запись больше не участвует в истории, графике и инсайтах.
- [ ] Если после удаления записи количество записей опускается ниже 3, инсайт переходит в статус `not_enough_data`, а прогресс показывает актуальное количество оставшихся до трёх записей.
- [ ] Пагинация и поиск по истории не входят в P0.

### US-6 · [P0] Оценка полезности инсайта
**Как** пользователь, **я хочу** оценить полезность инсайта, **чтобы** продукт мог отличать ценные выводы от бесполезных.

**Критерии приёмки:**

- [ ] Пользователь может пропустить оценку.
- [ ] Оценка не требует комментария и не превращается в опрос.
- [ ] После оценки пользователь получает короткое подтверждение без навязчивого продолжения.
- [ ] Оценка хранится без персональных текстов и не передаётся третьим лицам.

### US-7 · [P0] Компактный график за 7 дней
**Как** пользователь, **я хочу** увидеть компактную динамику всех показателей за неделю, **чтобы** визуально отслеживать своё состояние и замечать связи между метриками.

- [ ] Если записей нет, вместо пустого графика показывается понятное пустое состояние.

## 8. Основной сценарий (happy path)
1. Пользователь открывает приложение и видит быстрый вход в check-in.
2. Пользователь за 15–20 секунд выставляет 5 оценок и при желании выбирает предустановленные теги.
3. После сохранения записи пользователь видит прогресс до первого инсайта.
4. После 3 записей приложение проверяет явную связь сна и настроения.
5. Если явной связи пока нет, приложение ждёт до 5 записей и не делает ложный вывод.
6. После 5 записей пользователь видит найденный инсайт или сообщение, что связь пока не просматривается.
7. Если найден паттерн, пользователь видит одну мягкую рекомендацию.
8. Пользователь оценивает полезность инсайта или пропускает оценку.
9. Пользователь может открыть историю последних 14 записей и компактный график за 7 дней.

## 9. Крайние случаи и обработка ошибок
- **Записей меньше 3:** инсайт не показывается; вместо него показывается прогресс до 3 записей.
- **Записей 3–4, но явной связи нет:** система показывает прогресс до 5 записей без ложного вывода.
- **Записей 5+, но связь сна и настроения не видна:** система показывает `no_clear_pattern` и не показывает основную рекомендацию.
- **Сон почти не менялся:** система объясняет, что данных о различии сна пока мало.
- **Настроение сильно менялось при одинаковом сне:** система не связывает это со сном и предлагает продолжить наблюдение.
- **Пользователь пропустил день:** запись не создаётся автоматически; продукт не ругает пользователя и не использует наказующие формулировки.
- **Пользователь открывает check-in повторно за тот же день:** открывается редактирование существующей записи за этот день.
- **Пользователь редактирует старую запись:** после сохранения история, график и инсайт пересчитываются.
- **Нет записей для истории или графика:** показывается пустое состояние с предложением сделать первую запись.
- **Удалена запись, участвовавшая в инсайте:** история, график и инсайт пересчитываются или показывают, что данных пока мало.
- **Пользователь удаляет все данные:** после подтверждения продукт возвращается в состояние первого запуска без сохранённых записей.
- **Ошибка сохранения из-за нехватки места или сбоя хранилища:** продукт показывает понятное сообщение, сохраняет введённые значения на экране и предлагает повторить попытку.
- **Локальное хранилище повреждено:** продукт показывает нейтральную ошибку и не отображает некорректные данные как реальные записи.
- **Очень низкие оценки настроения/энергии несколько дней подряд:** в P0 отдельная кризисная логика не реализуется; продукт не ставит диагноз и не делает специальных выводов.

## 10. Нефункциональные требования
- **Скорость:** основной check-in занимает ≤15–20 секунд в демонстрационном happy path; проверяется сценарием из US-1.
- **Простота:** первый запуск не требует обязательной регистрации, настройки интеграций или длинного онбординга.
- **Офлайн:** все P0-сценарии работают без интернета.
- **Данные:** MVP работает с минимальным набором чувствительных данных; пользователь может удалить отдельную запись и все данные приложения.
- **Хранение:** в P0 нет облачной синхронизации; при удалении приложения или очистке данных ОС записи пропадают. Конкретная технология хранения фиксируется в `plan.md`.
- **Приватность:** нет сторонних аналитических SDK, передачи mood-данных третьим лицам и логирования личных записей в открытом виде.
- **Безопасность формулировок:** продукт не использует диагностические, медицинские, обвиняющие или категоричные выводы.
- **Визуальный язык:** безопасная палитра; красный не используется как прямой маркер «плохо». Детали — см. раздел 10.1 и `docs/palette.md`.
- **Доступность:** ключевые действия и тексты должны быть понятны без специальных знаний о психологии или статистике.
- **Локализация:** язык MVP — русский; мультиязычность не входит в MVP.
- **Платформа:** MVP — Android-приложение; целевой минимум для прототипа — Android 10 (API 29), финальная совместимость уточняется в `plan.md`.
- **Ограничения:** платные внешние API не используются.

## 11. Критерии приёмки прототипа (Definition of Done)
- [ ] Реализованы все истории P0, включая US-STAT.
- [ ] Главный сценарий проходится от начала до конца без критических ошибок.
- [ ] Check-in соответствует лимитам US-1: один основной экран, не больше 7 обязательных действий, ≤20 секунд в 2 из 3 демонстрационных попыток.
- [ ] Правило первого инсайта реализовано по разделу 5 и покрывает статусы `not_enough_data`, `waiting`, `found`, `no_clear_pattern`.
- [ ] Примеры из раздела 5.3 дают ожидаемый результат.
- [ ] Рекомендация показывается только при найденном паттерне и только одна за раз.
- [ ] История, график и инсайт пересчитываются после редактирования или удаления записи.
- [ ] Удаление всех данных возвращает приложение в состояние первого запуска.
- [ ] P0 работает без интернета и без обязательной регистрации.
- [ ] В продукте нет платных API, push-уведомлений, внешних трекеров, сторонних аналитических SDK и медицинской диагностики.
- [ ] Тексты и цвета не маркируют пользователя или его состояние как «плохое/неправильное».
- [ ] Нет критических багов, из-за которых пользователь теряет введённую запись без понятного сообщения об ошибке.
